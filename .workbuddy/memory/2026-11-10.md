## 庭院皮肤识别（engine/gui/costume_autodetect.py）
- 上游 17 套 `costume_main_1..17` + 默认皮肤，通过 `replace_img()` 换模板，**无自动识别**，识别逻辑建在壳子层。
- 三代实现迭代：
  1. 逐皮肤 `RuleImage.match()` + 固定 `roi_front` → 实测最高 0.44~0.75，全线失败。
  2. 全图灰度半分辨率粗筛 + 局部彩色复核。发现两个独立 bug：
     - **通道顺序**：`RuleImage.image` 是 RGB，`DroidCast_raw` 截图为 BGR；用 `frame.mean(axis=2)` 与通道无关。
     - **固定 ROI**：真实匹配点在 ROI 外（全图 1.000 / ROI 内 0.484），取景会漂 20~30px。
     - 提速约 27×（5092ms → 187ms）。
  3. **星座校验**（当前）：`I_CHECK_MAIN` 粗筛取前 4 → 用探索/召唤/町中/宠物屋等锚点验证「相对注册位置的平移偏移是否一致」，同偏移锚点数 ≥2 才采纳。解决 `main16`(狐栖归处 0.915) vs `main17`(玉岚狐庭 0.934) 相似皮肤碰撞。
- 结论：用户实际庭院为 **costume_main_17 玉岚狐庭**，配置里却是默认 `costume_main` → AreaBoss 报 `Page detect miss`。
- 鲁棒性验证：BGR/RGB/右移 80px/下移 60px 四种输入均正确，约 380~420ms。
- 缓存 `config/gui_costume_state.json`，TTL 3600s，adb 序列变化或实例离线即失效；总览「刷新识别」走 `force=True`。

## 进程残留与重装提示「正在运行」
- Electron `bridgeProc.kill()` = TerminateProcess，Python `atexit` 不执行 → OCR 守护孤儿。
- 四层防护：`taskkill /PID x /T /F`、`requestSingleInstanceLock()`、`--parent-pid` 看门狗（`OpenProcess(0x00100000)` + `WaitForSingleObject`）、bridge 侧 `proc_guard.py`。
- **本轮新发现**：electron-builder 安装器判「运行中」用的是
  `Get-CimInstance Win32_Process | ? { $_.Path.StartsWith('$INSTDIR') }` —— 任何 exe 路径以安装目录开头的进程都算。
- 真正的体感来源：`spawnSync('taskkill')` 阻塞主线程，点 X 后窗口消失但进程要等 taskkill 跑完才退；此时启动安装器就被判成「仍在运行」。
- 修复：退出全部改异步 `spawn(detached)+unref`，`beginQuit()` 加 1.5s 硬兜底 `app.exit(0)`；`!singleInstance` 从 `app.quit()` 改为 `app.exit(0)`（原写法会继续执行到 whenReady，留下无窗口僵尸）。

## 安装器「无法关闭」二次修复（1.1.7）
- 用户第二次反馈：重装仍弹「OAS Studio 无法关闭」，点重试才过。
- 该文案来自 `messages.yml: appCannotBeClosed`，即安装器已强杀 3 次、等了约 6 秒仍查到进程。
- 6 秒不够：Windows 上正在终止的进程（尤其卡在 D3D 收尾的 GPU 子进程）会在进程表残留十几秒。
- 修复分两侧：
  1. `console/build/installer.nsh` 定义 `customCheckAppRunning`（electron-builder 会把它注入为 common header，路径 `build/installer.nsh` 自动识别）：静默等 1.5s → 第 1.5s/6s 各强杀一次 → 等满 25s 才弹原对话框。
     坑：一旦定义该宏，`allowOnlyOneInstallerInstance.nsh` 顶部的 `Var pid` 不再声明，而 `KILL_PROCESS` 引用 `$pid` → `warning 6000` 被当错误（编译失败）。所以不能复用 `KILL_PROCESS`，要自己写 `nsExec::Exec` 的 Stop-Process 命令（`$$_` 转义 `$_`）。
  2. 应用侧 `beginQuit()`：1.2s 未退干净 → `sweepSiblings()` 用 PowerShell 杀掉「exe 路径相同且 PID≠自己」的兄弟进程；2.2s → `app.exit(0)`。不要用 `taskkill /PID <自己> /T /F`（taskkill 自身也是子进程，可能先把自己杀了）。

## 「无法关闭」的真正根因（1.1.8，已实测验证）
- 那个弹窗**不是** `CHECK_APP_RUNNING` 弹的，而是 `installUtil.nsh` 的 `uninstallOldVersion`
  （约 215-221 行）：它运行**上一版**的 `Uninstall OAS Studio.exe`，返回非 0 就重试 5 次，
  然后弹 `$(appCannotBeClosed)`（文案恰好也是「无法关闭」）。
- 旧卸载器为什么返回非 0：Python 桥接服务的工作目录是 `$INSTDIR\resources\engine`，
  进程里开着 `bridge.py` 和一堆 `.py/.pyc`，卸载器删不掉 → 失败。
- 而 `CHECK_APP_RUNNING` 的默认判据只认「**exe 路径**以 $INSTDIR 开头」，
  桥接的 exe 在 `%LOCALAPPDATA%\OAS Studio\runtime\python` → **完全看不见它**。
- 修法：判据扩成「路径在 $INSTDIR 下 **或** 命令行里出现 $INSTDIR」，
  后者正好命中 `python -X utf8 -B <INSTDIR>\resources\engine\gui\bridge.py`。
  另外用 `GetCurrentProcessId()` 排除自身 PID（防止安装包放在安装目录里自杀）。
- 实测验证：造一个命令行含 `D:\OAS Studio\resources\engine\gui\bridge.py` 的进程，
  旧判据返回 CLEAN，新判据返回 **FOUND**。
- 用户可见的验证点：安装时点「显示详细信息」应出现 `OAS: 检查上次的实例是否已完全退出…`。
- 全程不再弹框：2 秒后每轮先强杀再等待，45 秒兜底直接继续安装。

## 白屏 + 微软商店（1.1.9 修复，已实测）
- 现象：1.1.6~1.1.8 打开只有白框；启动/安装完成点「运行」还会弹 Microsoft Store。
- 根因：`console/main.js` 里
  ```js
  if (!singleInstance) return; // 已有实例在跑，本进程立刻退出  registerAppProtocol();
  ```
  —— 我在「退出改为异步回收」那次编辑里，把行尾换行一起替换掉了，`registerAppProtocol();`
  被并进了注释。于是 `app://` 协议从未注册：
  - `loadURL('app://oas/index.html')` 无法处理 → 文档是空的 `<html><head></head><body></body></html>`（白框）；
  - Win11 把未注册协议交给 ShellExecute → 没有关联程序 → **弹出 Microsoft Store**。
- 定位方法（值得复用）：`--remote-debugging-port=NNNN` 启动，再用原生 socket 手搓 WebSocket
  调 CDP `Runtime.evaluate`，直接读 `document.title` / `outerHTML.length`。空文档一眼可见。
  注意 WorkBuddy 环境里有 `ELECTRON_RUN_AS_NODE=1` 和 `NODE_OPTIONS`，必须 `env -u` 去掉，
  否则 Electron 会当 node 跑并报 `bad option`。
- 验证：修复后打包版标题 `OAS Studio · 阴阳师自动化控制台`、`outerHTML` 7344 字符、
  「引擎桥接已连接」都正常。
- 教训：`Edit` 工具替换带行尾换行的注释时，容易把下一行代码并进注释；改完要看一眼上下文。

## 构建/分发
- 构建命令（`.bin` 不存在，必须用 node 直调）：
  `node node_modules/electron-builder/out/cli/cli.js --win nsis -c.electronDist="node_modules/electron/dist"`
- 构建前必须清空 `dist/win-unpacked`（否则触发 safe-delete 拦截）；**清理和构建要分成两条命令**，
  同一轮删除配额会被算在一起。`find win-unpacked -mindepth 1 -delete` 最稳。
- `nsis.include` 的默认查找位置是 `buildResourcesDir`=`console/build`，已确认 `getResource` 源码。
